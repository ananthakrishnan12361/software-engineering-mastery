Programming Fundamentals, Variables, Data Types & Functions

Learning Objectives

  • Trace how source code is parsed, represented in memory (Stack vs. Heap), and executed by a runtime such as V8/Node.js.
  • Explain the exact difference between variable declaration, initialization, assignment, binding mutability, and the Temporal Dead Zone (var, let, const).
  • Distinguish all 8 ECMAScript data types, IEEE-754 floating-point precision limits, BigInt, and pass-by-value vs. pass-by-sharing semantics.
  • Design predictable, testable functions using pure transformations, higher-order composition, explicit boundary validation, and stack-safe iteration.
  • Recognize and prevent production bugs and security vulnerabilities caused by type coercion, 64-bit ID truncation, and unbounded recursion.

What is this?

Programming fundamentals are the core building blocks every software system relies on: how instructions are structured and executed, how data is named and stored in memory (variables), how the runtime interprets raw bits (data types), and how reusable units of logic accept inputs and produce outputs (functions).

Why does it exist & what problem does it solve?

CPUs only understand binary instructions and raw memory addresses. Writing large applications directly in binary or assembly is slow, error-prone, and tied to one hardware architecture. High-level languages such as JavaScript, TypeScript, Python, and Java solve this by giving engineers:

  • Named abstractions (variables) instead of raw hex memory addresses.
  • Data types so the runtime knows whether 01000001 means the integer 65, the character "A", or part of a floating-point decimal.
  • Functions to decompose complex business workflows into small, named, testable, reusable units with isolated local state.

Where is it used in real-world software?

Every layer of production software depends on these primitives. A React UI component is a JavaScript function returning UI descriptions from state variables. A Node.js/Express route handler is a function validating JSON types and transforming data. Even severe production outages—such as billing rounding errors, corrupted 64-bit database IDs in JSON, or authentication bypasses via loose type coercion—usually trace back to misunderstood fundamentals rather than exotic frameworks.

1. Programming Fundamentals: Expressions, Statements & Control Flow

A program is a sequence of instructions executed step by step unless redirected by control flow. Two terms cause frequent confusion:

  • Expression: Anything that produces a value (e.g., price * 1.1).
  • Statement: An instruction that performs an action (e.g., declaring a variable, branching with if, looping with for).

2. Variables: Labels, Not Boxes

Beginners often picture a variable as a physical box holding a value. A more accurate mental model is a sticky-note label attached to a slot in memory (for primitives) or pointing to an object in heap memory:

  • Declaration creates the label in the current scope (e.g., let total;).
  • Initialization gives it its initial value (e.g., let total = 0;).
  • Reassignment moves the label to point to a different value (total = 50;).
  • const prevents reassignment of the label, not mutation of an object's internal properties.

3. Data Types: The 8 ECMAScript Types

JavaScript is dynamically typed: variables do not have fixed types, values do. ECMAScript defines 8 data types—7 primitives and 1 reference type:

  • Primitives (immutable, stored/copied by value): number (64-bit IEEE-754 float), bigint (arbitrary-precision integers like 9007199254740993n), string (immutable UTF-16 code units), boolean (true/false), undefined (declared but unassigned), null (intentional absence of an object value), symbol (guaranteed-unique identifier).
  • Reference type (mutable, copied by reference value): object (plain objects, arrays, functions, Date, Map, Set, RegExp).

4. Functions: Inputs, Scope, Return Values & First-Class Citizenship

A function packages behavior under a name (or as an anonymous value), receives inputs via parameters (filled by arguments), runs inside a fresh local execution frame, and returns one value (defaulting to undefined if no return is executed).

In JavaScript, functions are first-class functions. That enables higher-order functions such as Array.prototype.map, Express middleware, and React hooks.

1. How a JS Engine Parses and Executes Code

Modern runtimes like Google V8 (used in Chrome and Node.js) do not simply read text line by line from disk:

  1. Lexing & Parsing: Source text is split into tokens and parsed into an AST. Syntax errors are caught here before a single line runs.
  2. Creation / Compilation Phase: Before executing a scope, the engine creates a Lexical Environment, registers bindings (var initialized to undefined; let/const placed in the TDZ; function declarations bound to their function object).
  3. Bytecode & JIT Optimization: V8's Ignition interpreter compiles the AST into compact bytecode and executes it. Hot functions (executed frequently with consistent types) are compiled to optimized machine code by TurboFan (JIT). If a type assumption breaks later (e.g., passing a string where an integer always arrived), V8 performs a deoptimization back to bytecode.

2. Stack vs. Heap Memory & Call Stack Frames

When a function runs, the engine pushes a new Stack Frame onto the Call Stack. Fixed-size primitive values (and references/pointers to objects) live in the fast, contiguous stack frame (or CPU registers). Dynamic, variable-sized structures like objects, arrays, and closures are allocated on the Heap, and the stack variable holds a reference (pointer) to that heap address.

3. IEEE-754 Double-Precision Floating Point & Tagged Values

Every JavaScript number uses the IEEE-754 64-bit binary floating-point format:

  • 1 bit for Sign (0 = positive, 1 = negative)
  • 11 bits for Exponent
  • 52 bits for Significand/Mantissa (plus 1 implicit leading bit = 53 bits of precision)

Because 53 bits of precision can represent integers exactly only up to 2^53 - 1 (9,007,199,254,740,991 = Number.MAX_SAFE_INTEGER), integers larger than this lose their least significant digits! Furthermore, base-10 fractions like 0.1 and 0.2 are repeating fractions in base-2 binary (just as 1/3 = 0.333... repeats in base-10), producing tiny rounding residues such as 0.1 + 0.2 === 0.30000000000000004.

Engine detail (V8): Internally, V8 optimizes common 31-bit/32-bit signed integers as Smi (Small Integers) stored directly inside tagged pointers without heap allocation, while fractional or large numbers become heap-allocated HeapNumber objects.

Example 3: Pass-by-Sharing, Pure Functions & Higher-Order Composition

// Pure function: depends only on inputs, does not mutate arguments
function calculateLineTotalCents(unitPriceCents, quantity, discountRate = 0) {
  if (!Number.isInteger(unitPriceCents) || unitPriceCents < 0) {
    throw new TypeError("unitPriceCents must be a non-negative integer");
  }
  if (!Number.isInteger(quantity) || quantity < 0) {
    throw new TypeError("quantity must be a non-negative integer");
  }
  const gross = unitPriceCents * quantity;
  return Math.round(gross * (1 - discountRate));
}

// Higher-order function returning a configured validator/calculator
function createTaxCalculator(taxRate) {
  return function applyTax(subtotalCents) {
    return subtotalCents + Math.round(subtotalCents * taxRate);
  };
}

// Pass-by-sharing: reassigning parameter does NOT affect caller; mutating property DOES
function testPassBySharing(obj, num) {
  num = 999;          // Reassigns local primitive copy only
  obj.touched = true; // Mutates shared heap object
  obj = { fresh: 1 }; // Reassigns local reference only; caller still points to old object
}

const payload = { id: 1 };
let count = 5;
testPassBySharing(payload, count);
console.log("Caller payload:", payload, "| Caller count:", count);

const applyVat = createTaxCalculator(0.2);
const subtotal = calculateLineTotalCents(1999, 2, 0.1);
console.log("Subtotal cents:", subtotal, "| With 20% VAT:", applyVat(subtotal));

Trace every runtime step of Example 3 (testPassBySharing and applyVat):

  1. Module Creation Phase: The engine parses all declarations, hoisting calculateLineTotalCents, createTaxCalculator, and testPassBySharing into the module lexical environment. payload and applyVat are registered in the TDZ.
  2. Execution — Heap Allocation: const payload = { id: 1 } allocates an object on the heap (say at 0x40A0) and stores the pointer 0x40A0 in the payload binding. let count = 5 stores primitive 5 directly in the count binding.
  3. Function Invocation — Stack Frame Push: testPassBySharing(payload, count) pushes a new frame onto the call stack. Parameter obj receives a copy of the pointer 0x40A0; parameter num receives a copy of the primitive 5.
  4. Inside Frame:
    • num = 999 overwrites the local num slot only; caller's count stays 5.
    • obj.touched = true dereferences 0x40A0 on the heap and adds property touched: true. Because caller's payload points to 0x40A0, caller observes the mutation.
    • obj = { fresh: 1 } allocates a brand-new heap object (say 0x99B0) and updates the local obj binding. Caller's payload still points to 0x40A0.
  5. Frame Pop: When testPassBySharing returns undefined, its stack frame is popped. The unreferenced 0x99B0 object becomes eligible for garbage collection.
  6. Higher-Order Return: createTaxCalculator(0.2) returns applyTax, which retains access to taxRate = 0.2 via its closure lexical environment even after createTaxCalculator's stack frame pops.

Scenario 1: Fintech & E-Commerce Ledger Calculations (Preventing Float Drift)

Problem: A SaaS invoicing backend built in Node.js sums line items stored as floating-point dollars (19.99 + 0.01 or 0.1 + 0.2). Over thousands of ledger rows, binary rounding residue causes trial balances to fail reconciliation by 1 cent ($100.00000000000001 !== $100.00).

Production Solution: Store and compute all monetary values in integer minor units (amountCents, e.g., 1999 for $19.99, or BigInt / arbitrary-precision decimal libraries for sub-cent FX rates) and format to decimals only at the UI presentation boundary.

Scenario 2: Node.js / Express Request Boundary Normalization

Problem: HTTP query parameters always arrive as string values (e.g., ?page=2&active=false). Treating "false" as a boolean directly fails because any non-empty string in JavaScript—including "false" and "0"—is truthy!

Production Solution: Write pure parser functions at the API boundary that explicitly check typeof, parse numbers with Number.isSafeInteger, and map "true" / "false" strings strictly before passing clean typed objects into business logic. 

function parseQueryFlags(query) {
  const page = Number(query.page ?? 1);
  if (!Number.isInteger(page) || page < 1 || page > 10000) {
    throw new RangeError("Invalid page parameter");
  }

  let active = null;
  if (query.active === "true") active = true;
  else if (query.active === "false") active = false;
  else if (query.active !== undefined) {
    throw new TypeError("active must be 'true' or 'false'");
  }

  return { page, active };
}

console.log(parseQueryFlags({ page: "3", active: "false" }));
  • Comparing floats with ===: Expecting 0.1 + 0.2 === 0.3 or 1.005 * 100 === 100.5 without tolerance (Number.EPSILON) or integer minor units.
  • Using loose equality (==): "" == 0, " \t\n " == 0, and null == undefined evaluate to true due to abstract equality coercion rules.
  • Checking for objects with typeof x === "object" alone: Forgetting that typeof null === "object" and typeof [] === "object". Always guard with x !== null && typeof x === "object" (and Array.isArray(x) for arrays).
  • Assuming Boolean("false") is false: Non-empty strings are always truthy. Aside from the legacy browser document.all quirk, only 8 values are falsy in JS: false, 0, -0, 0n, "", null, undefined, and NaN.
  • Mutating input objects inside helper functions: Modifying passed objects/arrays in place creates hidden side effects that break React change detection and cause spooky bugs across services.
  • Using var in loops with async callbacks: A single function-scoped var i is shared across every callback iteration, whereas let i creates a fresh lexical binding per iteration.
  • Default to const, use let only when reassignment is required, never use var in modern codebases.
  • Use strict equality (=== and !==) everywhere (except the rare intentional x == null check for both null and undefined, if team style allows it).
  • Prefer Number.isNaN, Number.isFinite, and Number.isSafeInteger over global isNaN / isFinite, because the Number.* methods do not coerce non-numbers first.
  • Keep core domain functions pure: accept explicit inputs, return new objects/values, push I/O (DB, HTTP, logging, clock) to the edges.
  • Validate at system boundaries (API handlers, message consumers, env vars) and keep internal helper signatures concise (prefer an options object if a function takes more than 3 parameters).
  • Enable "use strict" (automatic in ES modules and classes) so accidental global variables and silent assignment failures throw immediately.
  • Consistent Argument Shapes (Monomorphism): JIT engines optimize functions best when they consistently receive the same types and object property shapes. Passing mixed types (sometimes string, sometimes number, sometimes differently shaped objects) forces polymorphic/megamorphic lookups and deoptimizations in hot loops.
  • Call Stack Depth Limits: Typical JS engines allow roughly ~10,000 stack frames (varies by runtime and frame size). In Node.js/V8, Proper Tail Calls (PTC) are not enabled, so recursive algorithms on large trees or lists (100k+ nodes) will crash with RangeError: Maximum call stack size exceeded unless converted to an explicit stack/queue loop.
  • Allocation Pressure in Hot Loops: Creating temporary objects or cloning large arrays inside high-frequency loops increases Garbage Collection pause frequency. Keep pure immutability for application state, but consider pre-allocated buffers/arrays or controlled local mutation inside tight inner hot paths proven by a profiler.
  • BigInt Trade-off: BigInt arithmetic is slower than hardware-accelerated Smi/IEEE-754 Number operations and cannot be serialized directly by JSON.stringify() (throws TypeError). Use BigInt only where precision beyond 53 bits is genuinely required.
  • Type Confusion & Coercion Bypasses: If an API expects a string token or integer role ID and receives an array/object from unvalidated JSON (e.g., { "pin": [] } or req.query.id as an array ?id=1&id=2), loose checks or unguarded string methods can bypass authorization or crash the server. Always assert runtime types with a schema validator (e.g., Zod, Joi, Ajv).
  • 64-bit Database ID Truncation (Silent Data Corruption): PostgreSQL BIGINT or Snowflake IDs up to 2^63 - 1 exceed Number.MAX_SAFE_INTEGER (2^53 - 1). Parsing them as JS Number silently rounds adjacent user IDs to the same number, risking cross-user data exposure! Serialize 64-bit IDs as string in JSON APIs.
  • Unbounded Recursion DoS: Recursive JSON/AST walkers without a maximum depth guard allow attackers to send deeply nested payloads (e.g., 20,000 nested brackets) that crash the Node.js process via stack overflow.
  • Dynamic Code Execution: Never pass user-controlled strings to eval(), new Function(), or string-form setTimeout(); this leads directly to Remote Code Execution (RCE) on Node.js or XSS in browsers.

Basic 1. What is the difference between null and undefined in JavaScript?

Explanation: undefined means a variable has been declared, a property is missing, or a function has no explicit return—the runtime supplies it automatically as "not yet assigned." null is an explicit assignment value representing the intentional absence of an object or value.

Trap: typeof undefined === "undefined", while typeof null === "object" (a legacy 1995 bit-tag quirk). Also null == undefined is true, whereas null === undefined is false.

Example
let a; // undefined
let b = null; // explicitly empty
Follow-up & Tip

Follow-up: How does JSON handle both? JSON.stringify keeps null properties and drops undefined object properties.

Basic 2. What is the difference between var, let, and const?

Explanation: var is function-scoped, allows redeclaration, and is hoisted with an initial value of undefined. let and const are block-scoped, forbid redeclaration in the same scope, and remain uninitialized in the Temporal Dead Zone (TDZ) until their declaration line executes. const additionally forbids reassigning the variable binding, though objects referenced by a const binding can still be mutated.

Follow-up Question

Does const arr = [1, 2]; arr.push(3); throw an error? No—arr still points to the same array reference.

Interview Tip

Emphasize that const guarantees binding immutability, not deep data immutability (Object.freeze handles shallow property freezing).

Basic 3. What are the data types in JavaScript, and how do primitives differ from objects?

Explanation: JavaScript has 8 data types: 7 primitives (string, number, bigint, boolean, undefined, null, symbol) and 1 reference type (object, which includes arrays and functions). Primitives are immutable and compared/copied by value; objects are mutable and compared/copied by reference.

Example
"abc".toUpperCase() returns a new string; the original string cannot be altered in place.
Interview Tip

Remember BigInt (ES2020) and Symbol (ES2015)—many candidates forget them and say "6 types."

Basic 4. What is the difference between == and ===?

Explanation: === (strict equality) checks both type and value without type coercion (returning false immediately if types differ). == (abstract equality) performs multi-step implicit type coercion when operands have different types (e.g., converting strings/booleans to numbers), producing counterintuitive results like "" == 0 or [] == false.

Follow-up Question

How does Object.is(a, b) differ from ===? Object.is(NaN, NaN) is true and Object.is(+0, -0) is false.

Interview Tip

Always recommend === by default in production codebases enforced via ESLint (eqeqeq).

Intermediate 5. Why does 0.1 + 0.2 !== 0.3 in JavaScript, and how do you handle money safely?

Explanation: JavaScript numbers are 64-bit IEEE-754 binary floats. Just as 1/3 cannot be represented finitely in base-10, 0.1 (1/10) and 0.2 (1/5) are infinite repeating fractions in base-2. Rounding to 53 mantissa bits produces 0.30000000000000004 when added.

Practical Solutions: (1) Store money in integer minor units (cents) and compute using integers; (2) for arbitrary-precision decimals (tax rates, crypto, FX), use a decimal library such as decimal.js or big.js; (3) for scientific float comparisons, compare Math.abs(a - b) < Number.EPSILON (scaled by magnitude).

Follow-up

How do you round currency at tax time? Use integer arithmetic with deterministic rounding (e.g., half-even / banker's rounding when required by accounting rules).

Interview Tip

Mention that this is not a "JS bug"—Python, Java double, and Go float64 behave identically under IEEE-754.

Intermediate 6. Is JavaScript pass-by-value or pass-by-reference? Explain with an example.

Explanation: Strictly speaking, JavaScript is always pass-by-value, often termed pass-by-sharing for objects. For primitives, the value itself is copied into the parameter. For objects, the reference value (pointer) is copied into the parameter. Therefore, mutating a property (param.x = 2) affects the caller's object because both pointers target the same heap object, whereas reassigning the parameter (param = { x: 2 }) only rebinds the local parameter and leaves the caller unchanged.

Follow-up

How do you prevent a function from mutating caller data? Clone at the boundary (structuredClone or shallow spread { ...obj } for flat updates).

Interview Tip

Contrasting true pass-by-reference (like C++ int& x where reassigning x changes the caller variable) proves deep clarity.

Intermediate 7. Explain the Temporal Dead Zone (TDZ) and why let/const still hoist.

Explanation: Both let and const are hoisted to the top of their enclosing block during scope creation—meaning the engine knows the identifier exists in that block and shadows any outer variable of the same name. However, unlike var (initialized to undefined), let/const remain uninitialized in the TDZ until execution reaches their declaration statement. Reading them in the TDZ throws a ReferenceError—even typeof x throws inside the TDZ!

Code Proof
let x = 1; { console.log(x); let x = 2; } // ReferenceError, NOT 1!
Interview Tip

Point out that the inner let x shadows the outer x from the start of the block—proving let is hoisted.

Intermediate 8. What is a pure function, and why do React and backend pipelines care about purity?

Explanation: A pure function (1) always returns the same output for the same inputs (deterministic) and (2) causes no observable side effects (no mutating inputs/globals, no network/disk I/O, no Date.now()/Math.random()). Purity enables trivial unit testing without mocks, safe concurrency, memoization (caching by input), and predictable React rendering where shallow reference checks detect state updates.

Follow-up

Can an entire app be pure? No—real apps need DB writes and HTTP calls. Push side effects to thin I/O shells around a pure core ("Functional Core, Imperative Shell").

Interview Tip

Give a concrete example: Array.prototype.sort() mutates in place (impure), whereas toSorted() returns a new array (pure).

Advanced 9. How does V8 internally represent numbers vs. objects, and why can mixing types slow down a hot function?

Explanation: V8 uses pointer tagging to avoid heap-allocating every small integer. Small signed integers (Smi) are encoded directly in the pointer word with a tag bit, while floats and integers outside the Smi range are heap-allocated as HeapNumber objects. Similarly, objects share internal Hidden Classes (Maps) describing property offsets. When TurboFan JIT compiles a hot function, it specializes machine code for the observed Smi/object shapes (monomorphic). If later calls pass a string or differently shaped object, the type guard fails, causing deoptimization back to Ignition bytecode and megamorphic slow-path lookups.

Follow-up

How do you keep shapes consistent? Initialize all object properties in the same order in constructors/factories instead of adding properties dynamically later.

Interview Tip

Note clearly that Smi/Hidden Class details are V8 engine optimizations—not guarantees of the ECMAScript specification.

Advanced 10. Why does Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2 evaluate to true, and how does this break distributed systems?

Explanation: IEEE-754 double precision has 53 bits of significand precision (2^53 - 1 = 9,007,199,254,740,991). At 2^53, the spacing between representable floats jumps from 1 to 2, so odd numbers like 2^53 + 1 cannot be represented and round to 2^53. In distributed systems using 64-bit Snowflake IDs (Twitter/Discord style) or PostgreSQL BIGINT sequences, JSON.parse converts numeric literals into JS Number, silently corrupting IDs—two distinct records collide to the same ID.

Mitigation

Serialize 64-bit IDs as JSON strings ("id": "9007199254740993") or use BigInt internally with custom JSON revivers/serializers.

Interview Tip

Mention Number.isSafeInteger(val) as an essential validation guard on numeric IDs.

Advanced 11. Does JavaScript support Proper Tail Calls (TCO) in production, and how do you avoid call-stack overflow on deep data?

Explanation: Although ES2015 specified Proper Tail Calls in strict mode, major engines diverged: JavaScriptCore (Safari) implemented it, whereas V8 (Chrome/Node.js) and SpiderMonkey (Firefox) did not enable it due to stack-trace debugging concerns and low real-world ROI. Therefore, you cannot rely on tail recursion for unbounded inputs in Node.js or cross-browser apps—at ~10k+ depth, the call stack throws RangeError.

Production Alternatives: Rewrite recursion into an iterative loop with an explicit heap-allocated array stack/queue (while (stack.length)), or use a trampoline pattern (returning thunks) when recursive style is needed.

Follow-up

Why is an explicit heap stack safer than the call stack? Heap capacity scales to hundreds of MBs/GBs, whereas the call stack is typically a few MBs.

Interview Tip

Calling out the spec vs. V8 reality is a classic senior differentiator.

Advanced 12. Explain how JavaScript's abstract type coercion (ToPrimitive, ToNumber, ToBoolean) leads to subtle bugs and security flaws.

Explanation: When operators like +, ==, or relational < encounter mismatched types, the spec invokes internal abstract operations: ToPrimitive calls [Symbol.toPrimitive], valueOf(), then toString(). Meanwhile + prefers string concatenation if either operand becomes a string, whereas -/*/< convert to numbers (e.g., [] + {} === "[object Object]", Number([]) === 0, Number(null) === 0, Number(undefined) === NaN). If an auth or rate-limit check relies on if (limit > 0) or loose equality against unvalidated JSON/query parameters, unexpected arrays or empty strings silently coerce to 0 or true.

Defense

Validate exact runtime types at ingress using strict schemas (e.g., Zod) and disable implicit coercion via === + TypeScript strict mode.

Follow-up

What does null >= 0 vs null == 0 evaluate to? null >= 0 is true (ToNumber(null) === 0), while null == 0 is false (special spec rule for null/undefined).

Senior / Architect 13. Your multi-service Node.js + PostgreSQL + React platform is experiencing 1-cent billing discrepancies and occasional cross-account mix-ups on newly migrated 64-bit Snowflake IDs. Diagnose and design the fix end-to-end.
  1. How to analyze the problem: Trace data types across every boundary: DB column type → Node DB driver → JSON serializer → HTTP response → Browser JSON.parse → React state. Identify where 64-bit integers exceed 2^53 - 1 and where decimal amounts hit IEEE-754 floats.
  2. Requirements: Zero precision loss for money (multi-currency) and 64-bit IDs; zero downtime during migration; backward compatibility for existing API clients.

Exercise 1: Precision-Safe Invoice Splitter

Write a pure function splitAmountCents(totalCents, parts) that splits an integer cent amount evenly across parts participants without losing or creating a single cent (distribute any remainder cents one each to the first participants). Validate inputs strictly.

function splitAmountCents(totalCents, parts) {
  if (!Number.isSafeInteger(totalCents) || totalCents < 0) {
    throw new TypeError("totalCents must be a non-negative safe integer");
  }
  if (!Number.isSafeInteger(parts) || parts < 1) {
    throw new TypeError("parts must be a positive safe integer");
  }

  const base = Math.floor(totalCents / parts);
  const remainder = totalCents % parts;
  const result = [];

  for (let i = 0; i < parts; i++) {
    result.push(i < remainder ? base + 1 : base);
  }
  return result;
}

console.log("$10.00 / 3:", splitAmountCents(1000, 3)); // [334, 333, 333] -> sum is 1000

Exercise 2: Stack-Safe Iterative Array Flattener

Write a function flattenIterative(nested, maxDepth = 1000) that flattens arbitrarily nested arrays without recursion (so 20,000 nested arrays will not throw a stack overflow), while guarding against cyclic or excessively deep input.

function flattenIterative(nested, maxDepth = 1000) {
  if (!Array.isArray(nested)) {
    throw new TypeError("Input must be an array");
  }

  const output = [];
  const stack = [{ value: nested, depth: 0 }];

  while (stack.length > 0) {
    const { value, depth } = stack.pop();
    if (Array.isArray(value)) {
      if (depth >= maxDepth) {
        throw new RangeError(`Exceeded max nesting depth of ${maxDepth}`);
      }
      for (let i = value.length - 1; i >= 0; i--) {
        stack.push({ value: value[i], depth: depth + 1 });
      }
    } else {
      output.push(value);
    }
  }
  return output;
}

console.log(flattenIterative([1, [2, [3, 4]], 5]));
