<TopicSection id="m02-p3-sec-a" letter="A" title="Topic Introduction">

#### What is this?

Real-world React applications quickly outgrow local `useState` inside a single component. They require coordinated **client state management** (**Context API**, **Redux**, **Redux Toolkit**), asynchronous **server state caching** (**React Query / TanStack Query**), URL-driven navigation (**React Router**), schema-backed **forms and validation**, resilient **API integration**, and clear **authentication** vs. **authorization** boundaries.

#### Why does it exist & what problem does it solve?

Mixing UI state (open modals, selected filters), cached server data (orders, user profiles), form input state, and auth tokens into one ad-hoc store creates stale data races, duplicated `useEffect` fetch boilerplate, prop drilling, and security gaps. Separating each concern into the right tool keeps data flow predictable, debuggable, and fast.

#### Where is it used in real-world software?

Every production SaaS dashboard, e-commerce checkout, and internal admin portal combines these layers: **React Router** owns URL state and route guards, **TanStack Query** caches and deduplicates API reads/mutations, **Redux Toolkit** or **Context** manages shared client workflows, and **Forms + Validation + Auth** protect user inputs and session tokens.

</TopicSection>

<TopicSection id="m02-p3-sec-b" letter="B" title="Fundamentals (Simple Mental Models)">

<TopicAnchor id="m02-p3-topic-state-management" />

#### 1. State Management: Local, Shared Client, URL, and Server State

Not all state belongs in one global store. **Local UI state** (`useState`) lives in one component; **shared client state** (theme, multi-step cart drawer) lives in Context or Redux; **URL state** (active page, filters, search query) lives in **React Router**; and **server state** (API responses owned by the backend) belongs in **TanStack Query**.

Treating server data like synchronous client state forces teams to hand-write loading flags, error states, retry timers, and cache invalidation. Choosing the narrowest state owner for each piece of data eliminates entire classes of stale-UI bugs.

<TopicAnchor id="m02-p3-topic-context-api" />

#### 2. Context API: Dependency Injection Across the Component Tree

The **Context API** (`createContext`, `useContext`) passes shared values down a subtree without threading props through intermediate components (**prop drilling**). In React 19, you can render `<ThemeContext value={value}>` directly without `.Provider`.

Remember that **Context is a transport mechanism, not a high-frequency state engine**: every consumer calling `useContext(Ctx)` re-renders whenever the `value` reference changes by `Object.is`. Split fast-changing state from stable dispatch functions and memoize provider values.

<TopicAnchor id="m02-p3-topic-redux" />

#### 3. Redux: Predictable Single Store, Actions & Pure Reducers

**Redux** centralizes global client state in a single store updated through **one-way data flow**: UI dispatches a plain **action** (`{ type: "cart/added", payload }`), a **pure reducer** `(state, action) => nextState` computes a new immutable state snapshot, and subscribed components re-render selectively via selectors.

Because reducers are pure functions without side effects, Redux enables deterministic state transitions, middleware pipelines (logging, analytics), and time-travel debugging across complex multi-screen client workflows.

<TopicAnchor id="m02-p3-topic-redux-toolkit" />

#### 4. Redux Toolkit (RTK): Modern Standard Redux Without Boilerplate

**Redux Toolkit** (`@reduxjs/toolkit`) is the official, batteries-included way to write Redux. `createSlice` auto-generates action creators and action types, while **Immer** lets you write readable "mutating" syntax (`state.items.push(item)`) that safely produces an immutable copy under the hood.

`configureStore` sets up Redux DevTools, thunk middleware, and development-mode checks for accidental state mutations or non-serializable values—making legacy hand-written `switch` reducers obsolete.

<TopicAnchor id="m02-p3-topic-tanstack-query" />

#### 5. React Query / TanStack Query: Server State Caching & Synchronization

**TanStack Query** (`useQuery`, `useMutation`) manages **asynchronous server state**—data that lives remotely, can become stale, and may be shared across multiple components simultaneously. Queries are keyed deterministically (`["orders", { page, status }]`), deduplicated in flight, cached in memory, and refreshed automatically in the background.

Instead of storing fetched JSON inside Redux slices with manual `isLoading` booleans, `useQuery` gives you `staleTime` vs. `gcTime`, request deduplication, retries with exponential backoff, and `queryClient.invalidateQueries()` after mutations.

<TopicAnchor id="m02-p3-topic-react-router" />

#### 6. React Router: Declarative Routes, Params, Loaders & Protected Layouts

**React Router** synchronizes the browser URL (`/orders/42?tab=items`) with nested UI layouts using `<Outlet />`, dynamic params (`useParams`), query strings (`useSearchParams`), and programmatic navigation (`useNavigate`). Putting filter and pagination state in the URL makes views bookmarkable, shareable, and Back-button friendly.

Using nested layout routes (`<Route element={<RequireAuth />}><Route path="/billing" ... /></Route>`), you can enforce authentication and data loaders consistently before child routes render.

<TopicAnchor id="m02-p3-topic-forms" />

#### 7. Forms: Controlled, Uncontrolled & Schema-Driven Submissions

React **controlled inputs** bind `value={state}` and `onChange`, giving instant access for dynamic formatting or conditional fields—at the cost of re-rendering on every keystroke. **Uncontrolled inputs** (or **React Hook Form** via `ref` registration) keep keystroke state in the DOM and validate on blur/submit, keeping large 50-field forms fast.

Always handle **submission lifecycle states** explicitly (`idle`, `submitting`, `submitted`, `error`), disable duplicate submits while in flight, and preserve user-entered values if the API returns a `422` validation error.

<TopicAnchor id="m02-p3-topic-validation" />

#### 8. Validation: Client UX + Authoritative Server Contracts

**Client-side validation** (e.g., **Zod** schemas parsing email format, min/max bounds, and cross-field rules like `password === confirmPassword`) gives immediate accessible feedback (`aria-invalid`, `aria-describedby`) before a network round-trip.

However, **client validation is only UX—never security**. Attackers can bypass the browser with `curl`, so the backend must run authoritative schema validation on every request and return structured field errors (`{ field, message }`) that the frontend maps back to form inputs.

<TopicAnchor id="m02-p3-topic-api-integration" />

#### 9. API Integration: Typed Clients, Timeouts, Retries & Error Normalization

Production **API integration** centralizes `fetch` (or `axios`) behind a single typed HTTP client rather than scattering raw `fetch()` calls across components. The client attaches base headers, enforces `AbortSignal.timeout(...)` cancellation, normalizes HTTP errors (`401`, `403`, `422`, `503`) into typed domain errors, and checks `res.ok` before calling `res.json()`.

Combine **idempotency keys** on non-idempotent `POST` mutations with bounded retries only on safe `GET` or transient `502/503` failures—never blindly retrying a `400` or duplicate payment `POST`.

<TopicAnchor id="m02-p3-topic-authentication" />

#### 10. Authentication: Verifying Identity & Managing Session Tokens Safely

**Authentication (AuthN)** answers *"Who are you?"* by verifying credentials (password/passkey/OAuth2 + OIDC) and establishing a session. In modern SPAs, prefer **HttpOnly, Secure, SameSite cookies** set by a Backend-for-Frontend (BFF) over storing long-lived JWTs in `localStorage`, where any XSS script can exfiltrate them.

When short-lived in-memory access tokens expire (`401 Unauthorized`), a single-flight refresh coordinator ensures only **one** `/auth/refresh` request runs while concurrent API calls await the same promise instead of triggering a refresh storm.

<TopicAnchor id="m02-p3-topic-authorization" />

#### 11. Authorization: Enforcing Roles & Permissions Beyond Hidden Buttons

**Authorization (AuthZ)** answers *"What are you allowed to do?"* using Role-Based (**RBAC**: `admin`, `editor`, `viewer`) or Attribute-Based (**ABAC**: `order.ownerId === user.id`) checks. In React, route guards (`RequirePermission`) and UI conditionals (`can("invoice:approve")`) improve UX by hiding unauthorized views and avoiding wasted fetches.

Crucially, **frontend authorization is purely presentation logic**: every API endpoint and database query must independently verify permissions on the server, because client state and routes live in untrusted browser memory.

</TopicSection>

#### Example 2: Redux Store Core (`createStore`, Immutable Reducer, Re-Entrant Dispatch Guard)

<CodeBlock
  lang="javascript"
  runnable
  code={`// Models Redux core store semantics: single source of truth, pure reducer, listeners
function createReduxStore(reducer, initialState) {
  if (typeof reducer !== "function") throw new TypeError("reducer must be a function");
  let state = reducer(initialState, { type: "@@redux/INIT" });
  const listeners = new Set();
  let isDispatching = false;

  return {
    getState() {
      if (isDispatching) throw new Error("Cannot call getState while reducer is executing");
      return state;
    },
    dispatch(action) {
      if (!action || typeof action !== "object" || typeof action.type !== "string" || !action.type) {
        throw new TypeError("Action must be an object with a non-empty string type");
      }
      if (isDispatching) throw new Error("Reducers may not dispatch actions");
      try {
        isDispatching = true;
        state = reducer(state, action);
      } finally {
        isDispatching = false;
      }
      for (const listener of [...listeners]) listener();
      return action;
    },
    subscribe(listener) {
      if (typeof listener !== "function") throw new TypeError("listener must be a function");
      listeners.add(listener);
      return () => listeners.delete(listener);
    }
  };
}

function counterReducer(state = { count: 0 }, action) {
  switch (action.type) {
    case "counter/increment":
      return { count: state.count + (action.payload ?? 1) };
    default:
      return state;
  }
}

const store = createReduxStore(counterReducer);
let notifications = 0;
const unsubscribe = store.subscribe(() => {
  notifications++;
});
store.dispatch({ type: "counter/increment", payload: 2 });
store.dispatch({ type: "counter/increment", payload: 3 });
unsubscribe();
store.dispatch({ type: "counter/increment", payload: 1 });
console.log("Final count:", store.getState().count, "| Notifications:", notifications);`}

#### Example 3: TanStack Query Cache & In-Flight Request Deduplicator (`createQueryCache`)

<CodeBlock
  lang="javascript"
  runnable
  code={`// Models TanStack Query key serialization, staleTime freshness, and in-flight deduplication
function serializeQueryKey(queryKey) {
  if (!Array.isArray(queryKey) || queryKey.length === 0) {
    throw new TypeError("queryKey must be a non-empty array");
  }
  return JSON.stringify(queryKey, (_, v) => {
    if (v && typeof v === "object" && !Array.isArray(v)) {
      return Object.fromEntries(Object.keys(v).sort().map((k) => [k, v[k]]));
    }
    return v;
  });
}

function createQueryCache({ staleTimeMs = 30000, now = () => Date.now() } = {}) {
  const entries = new Map();
  const inflight = new Map();

  return {
    async fetchQuery(queryKey, fetcher) {
      if (typeof fetcher !== "function") throw new TypeError("fetcher must be a function");
      const key = serializeQueryKey(queryKey);
      const cached = entries.get(key);
      if (cached && now() - cached.updatedAt < staleTimeMs) {
        return { data: cached.data, source: "cache-fresh" };
      }
      if (inflight.has(key)) {
        const data = await inflight.get(key);
        return { data, source: "deduped-inflight" };
      }
      const promise = new Promise((resolve, reject) => {
        try {
          resolve(fetcher());
        } catch (err) {
          reject(err);
        }
      })
        .then((data) => {
          entries.set(key, { data, updatedAt: now() });
          return data;
        })
        .finally(() => {
          inflight.delete(key);
        });
      inflight.set(key, promise);
      const data = await promise;
      return { data, source: cached ? "revalidated" : "network" };
    },
    invalidateQueries(prefixKey) {
      const prefix = serializeQueryKey(prefixKey).slice(0, -1);
      for (const key of entries.keys()) {
        if (key === prefix + "]" || key.startsWith(prefix + ",")) {
          entries.set(key, { ...entries.get(key), updatedAt: -Infinity });
        }
      }
    }
  };
}

let clock = 1000;
let networkCalls = 0;
const qc = createQueryCache({ staleTimeMs: 5000, now: () => clock });
const loader = () => {
  networkCalls++;
  return { rows: ["ORD-1"] };
};
qc.fetchQuery(["orders", { status: "open", page: 1 }], loader);
qc.fetchQuery(["orders", { page: 1, status: "open" }], loader);
const keyA = serializeQueryKey(["orders", { status: "open", page: 1 }]);
const keyB = serializeQueryKey(["orders", { page: 1, status: "open" }]);
console.log("Keys match:", keyA === keyB, "| Network calls:", networkCalls);`}

function validateOrderForm(input) {
  if (!input || typeof input !== "object" || Array.isArray(input)) {
    throw new TypeError("Form input must be a plain object");
  }
  const errors = {};
  const email = typeof input.email === "string" ? input.email.trim() : "";
  const atIdx = email.indexOf("@");
  const domain = atIdx > 0 ? email.slice(atIdx + 1) : "";
  const hasWhitespace =

    email.includes(String.fromCharCode(9)) ||

  const validEmail =

  if (!validEmail) {
    errors.email = "Valid work email is required";

  const qty = Number(input.quantity);
  if (!Number.isInteger(qty) || qty < 1 || qty > 100) {
    errors.quantity = "Quantity must be an integer between 1 and 100";
  }
  return {
    valid: Object.keys(errors).length === 0,
    data: Object.keys(errors).length === 0 ? { email, quantity: qty } : null,
    errors
  };
}

function canActivateRoute(user, requiredPermission) {
  if (!requiredPermission || typeof requiredPermission !== "string") {
    throw new TypeError("requiredPermission must be a non-empty string");

  const perms = Array.isArray(user.permissions) ? user.permissions : [];

    return { allow: false, redirectTo: "/forbidden", status: 403 };

}

<TopicSection id="m02-p3-sec-e" letter="E" title="Step-by-Step Walkthrough">

Trace **`createQueryCache`** (**Example 3**) when two widgets request the same query concurrently:

1. **Deterministic Key Serialization:** `["orders", { status: "open", page: 1 }]` and `["orders", { page: 1, status: "open" }]` both serialize to `'["orders",{"page":1,"status":"open"}]'` because object keys are sorted.
2. **Freshness Check:** `entries.get(key)` is empty, so neither call hits `cache-fresh`.
3. **In-Flight Deduplication:** Call 1 registers its promise in `inflight.set(key, promise)`. Call 2 sees `inflight.has(key)` and awaits the **same** promise (`networkCalls` stays `1`).
4. **Invalidation:** Calling `invalidateQueries(["orders"])` marks matching entries stale (`updatedAt: -Infinity`) so the next mount triggers background revalidation.

</TopicSection>

<TopicSection id="m02-p3-sec-f" letter="F" title="Real-World Use Cases">

#### Scenario 1: Checkout Page With Mixed Client & Server State

**Problem:** A checkout team puts server-fetched shipping rates, cart UI drawer state, and coupon validation errors into one giant Redux slice, causing stale shipping quotes after address edits.

**Production Solution:** Keep shipping rates and order mutations in **TanStack Query** (`queryKey: ["shipping", zip]`, invalidated on address update), keep drawer open/close UI state in **Redux Toolkit** or local `useState`, and use **React Hook Form + Zod** for checkout fields.

#### Scenario 2: Multi-Widget Dashboard Experiencing a `401` Refresh Storm

**Problem:** Five dashboard widgets fire `fetch()` simultaneously right as the 15-minute access token expires. All five receive `401` and fire five separate `/auth/refresh` requests, revoking rotating refresh tokens on the server.

**Production Solution:** Coordinate refresh inside a shared HTTP client (`let refreshPromise = null`) so all five callers await the single in-flight refresh and then retry once with the updated session.

</TopicSection>

<TopicSection id="m02-p3-sec-g" letter="G" title="Common Mistakes">

- **Duplicating TanStack Query server data into Redux:** Creates two sources of truth that drift out of sync after mutations or background refetches.
- **Using a single monolithic Context for rapidly changing state:** Re-renders every consumer across the app on every keystroke or scroll tick.
- **Storing JWTs in `localStorage` or `sessionStorage`:** Exposes session tokens to any third-party script or XSS vulnerability on the origin.
- **Trusting React Router guards or hidden buttons as security:** Attackers can call backend endpoints directly—the server must enforce AuthZ on every request.
- **Retrying `400`/`422`/`401` or non-idempotent `POST`s blindly:** Causes duplicate orders or account lockouts instead of normalizing errors cleanly.

</TopicSection>

<TopicSection id="m02-p3-sec-h" letter="H" title="Best Practices">

- **Classify state before choosing a tool:** Local UI (`useState`), shared client workflow (`Context`/`RTK`), URL (`React Router`), server cache (`TanStack Query`), form state (`React Hook Form`).
- **Normalize API errors at the HTTP client boundary** and always check `if (!res.ok)` before parsing `res.json()`.
- **Share validation schemas (e.g., Zod)** between frontend forms and backend API handlers while treating server validation as authoritative.
- **Use `HttpOnly; Secure; SameSite` cookies** (or BFF sessions) for authentication, and pair them with CSRF protection when using cookie auth.

</TopicSection>

<TopicSection id="m02-p3-sec-i" letter="I" title="Performance & Scalability">

- **Request Deduplication & `staleTime`:** Setting sensible `staleTime` (e.g., `30s`–`5m` for reference data) eliminates redundant network waterfalls on route transitions.
- **Selector Granularity in Redux:** Use memoized selectors (`createSelector` from RTK/Reselect) so components only re-render when their derived slice actually changes.
- **Uncontrolled Forms at Scale:** For 40+ field enterprise forms, `ref`-based form libraries avoid re-rendering the entire form tree on every keystroke.

</TopicSection>

<TopicSection id="m02-p3-sec-j" letter="J" title="Security Considerations">

- **Authentication vs. Authorization:** Always enforce both on the backend—never rely on hidden React routes or disabled buttons (`<button disabled={!isAdmin}>`) for access control.
- **Token Storage & XSS:** Never persist bearer tokens in `localStorage`; prefer `HttpOnly` cookies via a BFF, and sanitize/avoid `dangerouslySetInnerHTML` everywhere.
- **Open Redirect Prevention on Login:** When redirecting back to `location.state?.from` after login, validate that the target is a safe relative path starting with `/` (not `//evil.example`) before calling `navigate()`.

</TopicSection>

<TopicSection id="m02-p3-sec-k" letter="K" title="Comparisons & Decision Tables">

#### 1. State Management Tool Selection Matrix

| State Type | Example | Best Tool | Why |
| --- | --- | --- | --- |
| **Local UI** | Accordion open, hover | `useState` | Co-located, zero boilerplate |
| **Low-Frequency Shared** | Theme, locale, current user | **Context API** | Built-in dependency injection |
| **Complex Client Workflow** | Multi-pane editor, undo/redo | **Redux Toolkit** | Predictable actions, DevTools, selectors |
| **Server Cache** | Orders, profiles, pagination | **TanStack Query** | Deduplication, `staleTime`, invalidation |
| **Navigation & Filters** | `/orders?page=2&sort=desc` | **React Router** | Shareable, Back-button safe |

#### 2. Client-Side vs. Server-Side Validation & Authorization

| Layer | Purpose | Can Be Bypassed? | Required In Production? |
| --- | --- | --- | --- |
| **Client Validation** | Instant field feedback | Yes (`curl`, DevTools) | Yes (UX & accessibility) |
| **Server Validation** | Reject malformed/malicious payloads | No | Yes (mandatory boundary) |
| **Route / UI AuthZ Guard** | Hide inaccessible pages/buttons | Yes (edit JS / direct HTTP) | Yes (UX clarity) |
| **Server API AuthZ** | Enforce RBAC/ABAC per resource | No | Yes (mandatory security) |

#### 3. Token Storage & Refresh Strategies

| Strategy | XSS Exposure | CSRF Exposure | Recommended Use |
| --- | --- | --- | --- |
| `localStorage` JWT | High (readable by any JS) | Low | Avoid for sensitive apps |
| `HttpOnly; SameSite=Lax` Cookie + BFF | Mitigated (`HttpOnly`) | Mitigated (`SameSite` + CSRF token) | Recommended default for SPAs |
| In-Memory Access Token + `HttpOnly` Refresh | Low (memory only) | Mitigated on refresh endpoint | High-security SPAs |

</TopicSection>

  <CodeBlock
    lang="javascript"

    code={`function createSliceReducer(name, initialState, handlers) {
  if (typeof name !== "string" || !name.trim()) throw new TypeError("name must be a non-empty string");
  if (!handlers || typeof handlers !== "object") throw new TypeError("handlers must be an object");

  const actions = {};
  for (const key of Object.keys(handlers)) {
    const type = name + "/" + key;
    actions[key] = (payload) => ({ type, payload });
  }

  function reducer(state = initialState, action) {
    if (!action || typeof action.type !== "string") return state;
    const prefix = name + "/";
    if (!action.type.startsWith(prefix)) return state;
    const key = action.type.slice(prefix.length);
    const handler = Object.hasOwn(handlers, key) ? handlers[key] : null;
    if (typeof handler !== "function") return state;
    return handler(state, action.payload);
  }

  return { reducer, actions };
}

const filters = createSliceReducer("filters", { query: "", page: 1 }, {
  setQuery: (state, query) => ({ ...state, query, page: 1 }),
  nextPage: (state) => ({ ...state, page: state.page + 1 })
});

const s1 = filters.reducer(undefined, filters.actions.nextPage());
const s2 = filters.reducer(s1, filters.actions.setQuery("react"));
console.log("State 1:", s1, "| State 2:", s2);`}

  prompt={
    <p>
      Implement <code>createAuthClient(&#123; request, refresh &#125;)</code> so concurrent <code>401</code> responses trigger only one <code>refresh()</code> call, retry each failed request once, and fail cleanly if refresh rejects.
    </p>

    lang="javascript"
    runnable
    code={`function createAuthClient({ request, refresh }) {
  if (typeof request !== "function" || typeof refresh !== "function") {
    throw new TypeError("request and refresh must be functions");
  }
  let token = "expired-token";
  let refreshInFlight = null;

  async function ensureFreshToken() {
    if (!refreshInFlight) {
      refreshInFlight = Promise.resolve()
        .then(() => refresh())
        .then((nextToken) => {
          if (typeof nextToken !== "string" || !nextToken) throw new Error("Invalid refreshed token");
          token = nextToken;
          return nextToken;
        })
        .finally(() => {
          refreshInFlight = null;
        });
    }
    return refreshInFlight;
  }

  return function fetchWithAuth(path) {
    if (typeof path !== "string" || !path.startsWith("/") || path.startsWith("//")) {
      throw new TypeError("path must be a relative path starting with a single /");
    }
    return (async () => {
      const first = await request(path, token);
      if (first.status !== 401) return first;
      const freshToken = await ensureFreshToken();
      return request(path, freshToken);
    })();
  };
}

let refreshCalls = 0;
const client = createAuthClient({
  request: (path, tok) => (tok === "fresh-token" ? { status: 200, path } : { status: 401, path }),
  refresh: () => {
    refreshCalls++;
    return "fresh-token";
  }
});

client("/api/orders");
client("/api/profile");
console.log("Auth client ready | Refresh calls queued:", refreshCalls);`}
  />

<TopicSection id="m02-p3-sec-q" letter="Q" title="Summary & Key Takeaways">

- **Right Tool per State Kind:** Keep UI state in `useState`/Context/RTK, URL state in React Router, and server cache in TanStack Query.
- **Redux Toolkit & Immer:** `createSlice` + `configureStore` eliminate Redux boilerplate while preserving pure, predictable state updates.
- **Forms & Validation:** Use schema validation on the client for fast accessible UX and on the server as the authoritative security boundary.
- **AuthN vs. AuthZ:** Protect tokens with `HttpOnly` cookies or in-memory + single-flight refresh, and enforce permissions on the server—never only in React Router.

</TopicSection>
